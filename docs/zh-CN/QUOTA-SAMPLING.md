# 固定每小时读取额度

目标是让 AFC 发起的 Claude、ChatGPT、SuperGrok、Cursor、Antigravity 额度读取共用固定一小时周期，同时让本地保护继续及时发布。英文完整设计见 [QUOTA-SAMPLING.md](../QUOTA-SAMPLING.md)。

首个读取在 `quota-sampling.json` 建立持久锚点，后续按 `anchor + n × 1 小时` 分槽。每个来源每槽至多尝试一次；新启用的来源可在当前槽初始化一次。成功、失败、页面访问和设置修改都不移动锚点。停机错过的槽不追补，恢复时只尝试当前槽。失败保留原错误和旧样本时间，下个槽再试。

| 工作 | 周期 | 约束 |
|---|---|---|
| Paseo provider 批量读取 | 每小时槽一次 | Claude、ChatGPT、SuperGrok 共享一次批量调用。 |
| Grok 屏幕、Cursor API／屏幕、Antigravity CLI、可选 Codex coupon／credits CLI | 同一小时槽 | 面板、确认 coupon、登录状态刷新都不能绕过调度；关闭的来源不启动。 |
| pool／matrix 保护发布 | 每分钟或设置触发 | 按当前时间评估已有读数、手动关池、禁用、角色范围、重置及过期；不新增额度读取。priority 原有 30 分钟有效期由此续期。 |
| 展示 | 原有面板刷新周期 | 面板更新时间、额度来源时间、AFC 调用时间、用量统计时间分别标注。 |
| 展示新鲜度 | 62 分钟以内 | 重置或显式过期时间可以让读数更早过期；总览读取缓存时重新判断。 |
| 派活保护 | 原有短有效期 | 配置式 live 读数及已证明同池的 ACP 保持 7 分钟；手抄 TTL、Grok 2 小时值保留、Cursor 失败后 30 分钟值保留不延长。 |

Antigravity CLI 展示期限由 7 分钟变为 62 分钟，ACP 安全期限仍是 7 分钟。Cursor 成功读数新增 62 分钟展示过期，legacy provider 值在 2 小时或重置后不再作为可用值。受 7 分钟规则保护的池，在成功的一小时采样周期内仍可能停派约 53 分钟；这不是读取失败。合同快照 TTL 保持 900 秒，消费者原有 45 分钟 stale 和 15 分钟报警也不变。

额外保护变化须交审查：已知 Cursor／Grok 耗尽的读数不会因后续失败、展示过期或较低手抄值而消失；有效新读数或已知重置才能解除，Grok 也可用时间更晚的 provider 来源证明。来源关闭后不继续应用旧 CLI 记录。实际已有 quota／rate_limit／认证失败信号对相应池生效；`quotaProtection: none` 仍允许未知 ACP，未证明同池的 CLI 读数或 CLI 失败不能当作 ACP 额度信号。

来源时间缺失、损坏或在未来时显示“未知”。Paseo legacy `fetchedAt` 是全批最早时间，标成“批量来源”，不能当作各账号精确时间。AFC 的原始调用时间独立显示，缓存返回及新的 `generatedAt` 不刷新旧额度年龄。Grok CLI 百分比和时间来自同一次真实读取。

进程内并发共用 Promise。同宿主、同状态目录的进程通过短文件锁串行持久预占；不承诺跨宿主、不同目录、断电或分布式文件系统保障。预占后崩溃会消耗该槽。遗留锁／损坏调度文件会拒绝采样，owner 确认没有读取进程后才能清理；不要盲删状态文件，因为删除会允许重新初始化。

AFC 当前只订阅 `agent.turn_ended` 做用量记账，没有通用 provider 失败事件流。已有 Cursor 登录状态与匹配的读取失败会传播到本地保护；其它入口的失败需要 owner 在 Fleet Settings 将相应 plan 的 `dispatch` 关闭。通用失败接口留给宿主集成后续处理。小时之间的未知消耗最长约一小时加 timer／reader 延迟才能观察到，不能保证绝不超额。

交付范围为公共源码、本地构建和回归；不改安装树、私有配置、合同或模型审查规则，不 push、开 PR、合并、发版或重启日常宿主。后续部署保留调度锚点与并行私有配置，使用 CAS。源码回退兼容新增字段，但会恢复旧采样频率，不能声称仍是每小时。

本地按 README 安装依赖，运行 `npm run build`、目标回归和 `npm run verify` 完整门禁；实际编译器、兄弟仓库及合同校验必须有真实结果。fake clock／子进程使用合成数据，不读取凭证或调用真实来源。

真实 Edge／桌面验证须另卡：匿名隔离宿主、provider disabled、零模型任务；核对五来源窗口的读取时间／未知时间／旧数据，面板新但额度旧的状态，打开关闭及重启恢复。RC 安装、升级、回退另卡，保留私有配置。组件 mount 或快进时间不能替代真实面板验收，也没有证明原先报告的 6 小时 UI 问题根因。
